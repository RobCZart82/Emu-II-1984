## Confirmed defect

The main memory read API deliberately returns 0xFF outside its mapped ROM/RAM,
and writes to those addresses are ignored. The offline trace used those
operations without checking whether the backing existed. As a result, a
jump to 0x2800 could execute fabricated RST instructions and produce further
trace rows. Data reads and writes could likewise continue through unknown
hardware. The baseline evidence is tools/z80_rom_trace.cpp lines 27–41 and
src/core/main_memory.cpp lines 35–50.

The trace now stops on the first unmodelled memory transaction. The mapping
query follows each bus's page selectors and reset override. The appended CSV
field records the physical address. Synthetic tests cover instruction fetch,
data read/write and a page-select output followed by an unmapped fetch.

## Documentation discrepancy

ROM_OS_MATRIX.md still asserted that firmware execution had never occurred,
while LOCAL_INPUTS.md recorded bounded local traces. Updated the matrix to
refer to those later observations. Historical log entries retain their dates.

## Reviewed behavior and open work

The event scheduler maintains tick/phase/FIFO ordering, preserves its phase
floor after exceptions and rejects recursive dispatch. Existing tests exercise
chunked replay. CPU callbacks still execute whole instructions, so IRQ, WAIT
and DMA arbitration require a bus-yield strategy before shared CPU timing.

The inspector bounds direct/member reads and archive metadata, preserves
duplicate member identities and checks HFE storage overlap. HFE content/CRC,
PROM wiring and compatibility remain open research tasks. Reports about the
private corpus were read as historical evidence and were not independently
reproduced during this audit.

The current trace stops after partial instruction effects at an unknown access.
It provides an observation boundary. Resuming such a CPU requires explicit
state recovery. Original firmware, OS boot, audio and DAW behavior were not
used as acceptance evidence for this change.
